# 编写能支撑小说的种子

小说种子简要说明故事以及作者可以依赖的事实。它为创作者自己的 AI 提供逐拍起草的方向，不要求 Synapse 发明正典或正文。

## 提供给 Synapse 的内容

先写故事前提、主角的具体目标、阻碍目标的力量、时间跨度和结局方向。只有确实要检查的事实或规则才写入。年龄和性别是可选的；如果在种子中提供，Synapse 会把它们作为正典值提议给创作者确认。

## 一个可用种子的五个部分

1. **前提：** 故事跟随谁，什么事情会改变。
2. **目标：** 人物必须做什么，以及期限。
3. **阻力：** 让目标变难的人、规则、处境或选择。
4. **时间与结局方向：** 事件发生的时间，以及故事结尾可能出现的变化。尚未决定的细节可以留白。
5. **人物与正典：** 人物姓名、可选的年龄和性别、已确认的规则，以及检查器能检查的状态事实。不要为了填字段而添加事实。

## 先规划场景，再写正文

每个场景包含一个请求、场景人物和 1–12 拍。为每拍写明起始状态、结束状态和参与行动者。行动者必须属于场景人物。计划有问题时不会保存。修改文件后，在终端确认计划的确切哈希。

## 一拍请求包含什么

确认计划后请求第一拍。Synapse 返回共享写作提示、已确认的正典文本块及其哈希，内容包含本拍的起始状态、结束状态和行动者；后续拍还会收到已锁定的上一拍。Synapse 不会把请求发送给模型。请交给自己的 AI，或亲自写作。

## 检查会告诉你什么

`check` 将文本与写作者看到的正典对照，并检查计划中的行动者是否都出现在文本里。结果会报告确定冲突、可能冲突、未检查值，以及正典是否一致（`facts_match`）。只有没有确定冲突和未检查项，所有计划行动者都出现在文本中，并且已确认计划哈希一致时，才可锁定。可能冲突和未检查值不会阻止锁定：终端会显示两者，锁定记录会连同创作者自己的话保留它们。质量审查只是建议，不会阻止锁定。即使仍有未确认要求而导致 `complete` 为假，某拍也可能满足锁定条件。

创作者查看可能冲突和未检查值后，在终端锁定检查通过的拍。同一场景的下一拍要等上一拍锁定。若正文、正典文本块或计划哈希后来改变，`status` 会将其标为 stale。只有所有拍已锁定且没有 stale 项，才能合成场景；只要有一拍 stale 或未锁定，`assemble` 就会拒绝整个场景且不写入输出。成功输出路径必须是新文件。

## 随附的合成示例

[`novel/README.md`](novel/README.md)介绍了灯塔故事的种子卡、名为 `ch1s1` 的单场景计划和三拍文本。这些合成数据展示输入格式。正典值、请求、检查结果、回执和锁定记录会写在用户自己的项目文件夹中。

## 开始一个项目

在 `editions/novel/` 中创建项目文件夹并使用示例种子。用自己的话逐项确认提议值，然后提交单场景计划：

```text
python synapse_novel.py novel seed --project P --seed-file examples/novel/seed.json
python synapse_novel.py canon values confirm P/novel/canon-values.json KEY --files P/novel
python synapse_novel.py novel plan --project P --plan-file examples/novel/plan.json
python synapse_novel.py novel plan-confirm --project P
```

请求一拍，将返回的请求交给自己的 AI，把生成的文本保存为 UTF-8 文件，然后运行 `novel check`。若结果可锁定，查看显示的未检查值，并在终端运行 `novel lock`。其余拍重复此流程，最后合成场景。
